# unread-forever

<img src="extension/icons/icon128.png" width="80" height="80" alt="icon">

> 专治想知道谁赞了我但又不希望攒的999+消失的特殊癖好患者（比如我）

**安装**：对于Chrome：`chrome://extensions/` → 开发者模式 → 加载已解压的扩展程序 → 选 `extension` 目录。
对于Edge同理，把`chrome://extensions/`换成`edge://extensions/`就行

## 能干什么

- 消息中心里点击：谁赞了你、谁回复了你、谁 @ 了你不会清除红点，刷新网页后红点还在。
- 右下角常驻「红点守护中 · 已拦截 N 次」，记录拦截次数；
- 不读 Cookie、不连服务器、没有构建和依赖，即装即用。

## 怎么做到的

B 站的消息列表接口，带不带 `id` 是两种语义：

| 请求 | 服务端理解 | 结果 |
| --- | --- | --- |
| `/x/msgfeed/like?...` | 用户打开了标签页 | 已读游标推到当前时间，红点消失 |
| `/x/msgfeed/like?...&id=9000000000000000000&like_time=…` | 用户在往下翻页 | 返回数据，游标不动 |

插件在请求离开浏览器前，给 `/x/msgfeed/like|reply|at` 补一个雷霆大 `id`，
于是每次请求都被当成翻页：数据照常返回、页面照常渲染、已读状态一动不动。

`fetch` 和 `XMLHttpRequest` 都挂了钩子（B 站用 axios，走 XHR），只匹配这三个路径，其它请求一律不碰。

> 一个无关紧要的副作用：消息中心页面会自己把顶部的未读数字清成 0，那只是当前标签页的前端状态，刷新后就会恢复。
